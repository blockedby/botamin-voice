# Post-booking qualification

## Ownership and scope

Этот файл определяет только необязательное обогащение уже созданной внутренней брони.

## Preconditions

Начинай квалификацию, только если одновременно выполнено всё:

- server context содержит существующий `bookingId` и статус `booked`;
- успешное создание брони уже подтверждено пользователю;
- пользователь согласился ответить на дополнительные вопросы;
- `append_booking_qualification` присутствует в `allowedActions`.

Если хотя бы одного условия нет, не задавай квалификационный вопрос и не вызывай qualification tool.

## Question selection

После отдельного явного согласия собери ровно два поля:

1. сначала месячный объём входящих лидов — сохрани в `monthlyLeadVolume`;
2. затем явное число менеджеров продаж — сохрани целым числом в `salesManagerCount` без домысливания.

Задавай строго один вопрос за раз. Если пользователь сам сообщил второе поле раньше первого, сохрани его и спроси только отсутствующий месячный объём лидов. Если в одной реплике сообщены оба поля, передай оба одним patch и не задавай следующий вопрос. Не повторяй известное и не спрашивай другие qualification-поля.

## Patch and stopping rules

- После каждого содержательного ответа вызови `append_booking_qualification` для той же брони; patch может содержать одно или оба поля.
- `completion` — только предложение модели: backend сам определяет `partial` или `complete` по объединённым сохранённым полям.
- После partial tool result задай только конкретный отсутствующий второй вопрос, который сообщает server context/result.
- Не добавляй поля, которых пользователь не сообщал и которые server context не подтверждает.
- При отказе до первого вопроса прекрати квалификацию со skipped. При отказе после одного ответа сохрани partial и больше ничего не спрашивай и не продавай. Существующая бронь остаётся `booked`.
- В конце кратко поблагодари и не предлагай создать бронь повторно.

# Post-booking qualification

## Ownership and scope

Этот файл определяет только необязательное обогащение уже созданной внутренней брони.

## Preconditions

Начинай необязательную квалификацию без отдельного permission turn, только если одновременно выполнено всё:

- server context содержит существующий `bookingId` и статус `booked`;
- успешное создание внутренней виртуальной встречи уже правдиво подтверждено пользователю в этой же или предыдущей реплике;
- `append_booking_qualification` присутствует в `allowedActions`.

Если хотя бы одного условия нет, не задавай квалификационный вопрос и не вызывай qualification tool. Явный отказ пользователя в любой момент немедленно завершает квалификацию, но не отменяет встречу и уже сохранённые facts.

## Question selection

Собери не более двух полей, но только если они отсутствуют в authoritative server facts и booking qualification:

1. месячный объём лидов или обрабатываемых контактов — сохрани в `monthlyLeadVolume`;
2. явное число менеджеров продаж — сохрани целым числом в `salesManagerCount` без домысливания.

После правдивого подтверждения встречи сразу выбери первый отсутствующий факт без отдельного вопроса о разрешении. Если оба поля отсутствуют, сначала спроси месячный объём; если одно уже известно, спроси только другое; если оба известны, не задавай qualification-вопросов и заверши. Никогда не повторяй значения `monthlyLeadVolume` или `salesManagerCount`, уже известные из server facts.

Вопрос об объёме адаптируй к подтверждённому контексту: для входящего процесса спроси о входящих лидах или обращениях, для исходящего — об обрабатываемых исходящих контактах, для смешанного или неизвестного — о лидах или контактах, обрабатываемых за месяц. Не своди вопрос всегда только к входящим лидам.

Число менеджеров должно быть явным целым количеством именно менеджеров продаж в команде пользователя; не принимай за него размер всей компании, колл-центра или внешней команды.

Задавай строго один вопрос за раз. Если в одной реплике сообщены оба отсутствующих поля, передай оба одним patch и не задавай следующий вопрос. Не спрашивай другие qualification-поля.

## Patch and stopping rules

- После каждого содержательного ответа вызови `append_booking_qualification` для той же брони; patch может содержать одно или оба отсутствовавших поля.
- Если пользователь назвал объём просто «в день» без явного основания, сначала уточни: «Это по рабочим или календарным дням?». Не нормализуй и не сохраняй месячный объём до ответа об основании.
- Явно названный объём за рабочий или календарный день может быть нормализован сервером. Сам не вычисляй и не утверждай умножение на 22 или 30 дней.
- `completion` — только предложение модели: backend сам определяет `partial` или `complete` по объединённым сохранённым полям.
- После partial tool result задай только конкретный отсутствующий вопрос, который сообщает server context/result.
- Не добавляй в patch уже сохранённые поля и поля, которых пользователь не сообщал или которые server context не подтверждает.
- При явном отказе в любой момент прекрати квалификацию: без ответов сохрани skipped, с одним сохранённым фактом оставь partial; больше ничего не спрашивай и не продавай. Существующая встреча остаётся `booked`.
- В конце кратко поблагодари и не предлагай создать встречу повторно.

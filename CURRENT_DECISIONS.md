# Current decisions

**Spec:** `0.5-demo`
**Status:** authoritative active decisions

- Release sequence is **local hosting first**. `v0.5.0-local-rc.4` is recommended but pending; no tag, PR, or release hash is claimed here. Target VPS, public TLS/WSS, target-host live booking, full Chromium voice journey, and WebKit full-journey acceptance remain external gates.
- On landing entry the browser makes exactly one attempt to play the committed same-origin proactive MP3. Before both consents it performs no conversation REST, WebSocket, microphone, provider, or session action. Block/error exposes `Включить приветствие`; real session start stops/releases the greeting.
- Proactive greeting and local reaction assets are static product assets. Their generation scripts are explicit paid administrator opt-ins; ordinary visits never synthesize them. The 16 reaction assets are already committed and require zero runtime provider calls.
- OpenRouter is the only STT/TTS gateway after consent. One backend-only `OPENROUTER_API_KEY` authorizes both; the browser receives neither credentials nor raw provider responses.
- Input pipeline: **browser PCM16 chunks → bounded gateway utterance → one validated WAV → atomic `audio/wav` `SttPort` request → OpenRouter final transcript → Codex subscription / `gpt-5.6-luna`**. The only STT text event is `transcript.final`; stale/aborted results cannot reach Luna or tools.
- Speech prompts require concise natural Russian: normally no more than two short sentences, one useful idea, and at most one question, without filler acknowledgements or invented progress.
- TTS starts at most two ordered requests at once (current phrase plus one prefetch). Results publish in source order; first failure, interruption, or stale generation suppresses later prefetched audio without repeating brain or business effects.
- The browser renders provider-neutral complete MP3 or canonical WAV segments. Web Audio schedules decoded segments against the preceding end time for gapless playback. A credit protocol bounds retained audio to four segments / 20 MB / 5 MB each, with no more than two decoded/source slots; credit returns only after release.
- Playback `AudioContext` creation/resume belongs to the consent gesture's synchronous path, before microphone or network awaits. This is required for WebKit-style gesture ownership and still needs live WebKit journey evidence.
- Capability negotiation gates 16 same-origin reaction clips. At most one eligible clip per turn is requested after 350 ms; stage, privacy/exact-fact, allowlist, staleness, mute, and barge-in fences can suppress it. Reactions do not create transcript/state/provider/business effects.
- The default TTS profile remains `OPENROUTER_TTS_PROFILE=xai_mp3`, model `x-ai/grok-voice-tts-1.0`, case-sensitive voice `eve`, and `OPENROUTER_TTS_RESPONSE_FORMAT=mp3` unless the environment is deliberately changed.
- The opt-in Gemini profile requires all four exact values together: `OPENROUTER_TTS_PROFILE=gemini_3_1_pcm`, `OPENROUTER_TTS_MODEL=google/gemini-3.1-flash-tts-preview`, one supported case-sensitive voice, and `OPENROUTER_TTS_RESPONSE_FORMAT=pcm`. `OPENROUTER_TTS_SPEED` must be empty/unset.
- The case-sensitive Gemini release snapshot verified 2026-08-03 contains exactly 30 voices: `Zephyr`, `Puck`, `Charon`, `Kore`, `Fenrir`, `Leda`, `Orus`, `Aoede`, `Callirrhoe`, `Autonoe`, `Enceladus`, `Iapetus`, `Umbriel`, `Algieba`, `Despina`, `Erinome`, `Algenib`, `Rasalgethi`, `Laomedeia`, `Achernar`, `Alnilam`, `Schedar`, `Gacrux`, `Pulcherrima`, `Achird`, `Zubenelgenubi`, `Vindemiatrix`, `Sadachbia`, `Sadaltager`, `Sulafat`.
- Gemini is Preview and its public catalog is dynamic. Configuration fails closed for model/profile/format/voice mismatch; there is no automatic catalog refresh, model/voice choice, or fallback to xAI. Roll back by restoring the exact four-value xAI profile above.
- OpenRouter Gemini PCM never crosses the server boundary raw. The adapter validates complete PCM16LE, wraps it as canonical mono 24 kHz PCM16LE WAV with one 44-byte RIFF header, and publishes only the complete `audio/wav` file.
- Delivery style is trusted server presentation metadata: `neutral`, `curious`, `serious`, or `excited`. Gemini receives only fixed server-owned tags (`neutral` has no tag); visitor/model-authored bracket controls are rejected. Contacts, exact meeting/date/time facts, booking/qualification facts, server authority/fallbacks, interrupted turns, and other sensitive content always use neutral. The visible transcript remains plain text and durable state stores no style effect.
- TTS redacts contacts by default. The only exception requires active contact-processing consent and an exact server-approved contact from accepted durable draft facts or the committed booking; arbitrary/model-supplied contacts stay redacted.
- Each utterance is capped at 60 seconds and the atomic STT WAV at 2,000,000 bytes. The circular UI countdown comes from accepted 16 kHz PCM16 samples and the stricter server-advertised duration/byte ceiling, not wall time.
- Provider-neutral `visitor.text.submit` carries one bounded final typed turn, supersedes uncommitted microphone bytes, and follows the same fact extraction, Luna, state, tool, persistence, assistant, and optional TTS path as speech.
- RC4 uses one durable revisioned `conversation_contexts.draft_json` per conversation for facts/provenance/conflicts, exactly two candidate identities, selection, readiness, confirmation/commit state, and booking identity. Browser projections strip provenance/evidence; expected-revision CAS and idempotency fail closed.
- The structured in-chat form patches that same draft and cannot fabricate a booking. Exact current-revision confirmation automatically commits one durable internal booking and publishes the server-derived `internal_virtual` / `scheduled` meeting projection with both external calendar flags false.
- Booking requires accepted name, company, working email, phone or Telegram, consent, and one of exactly two current internal 20-minute Moscow candidates. Candidates are concretely dated non-today weekday starts on the 09:00–17:00 20-minute grid, not exhaustive global availability.
- Optional qualification starts directly after truthful meeting confirmation, asks only missing volume/manager facts, and never removes the scheduled meeting on refusal, partial answer, disconnect, or provider failure.
- Sales cadence remains moderately proactive: no more than two discovery questions before a soft offer. The 10–15 million RUB/month claim is allowed only as an attributed user-brief claim, never a guarantee.
- On this host on 2026-08-03, the Schedar neutral smoke succeeded through OpenRouter: `audio/wav`, 188204 bytes, 3326ms. This is not a quality claim and does not close a browser/full-journey gate.
- No formal voice A/B matrix exists. Provider-listening quality, full Chromium/WebKit voice journeys, target-host provider booking, and target-host latency/load remain gates.
- Prompts remain Markdown and the app remains one TypeScript full-stack Compose deployment. `scripts/deploy-local.sh` materializes file-backed secrets, protects an existing DB, migrates through normal startup, waits for readiness, and runs the PII-safe RC4 invariant check without paid smokes.
